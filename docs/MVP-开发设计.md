# 科普内容再创作工具：MVP 开发设计

## 1. 产品定义

一个供个人本地使用的 Web 工具。用户粘贴一篇已有科普文章，系统调用 OpenAI 模型完成清洗、重组和分镜规划，输出：

- 一组统一视觉风格的 HTML 讲解页；
- 每页对应 30–60 秒的中文口播稿；
- 可预览、逐页修改、重新生成及导出的内容包。

首期目标是跑通“文章到图文讲解页与口播稿”的高质量闭环，不生成图片、视频、配音，也不联网检索。

## 2. 首期边界

### 做

- 文章粘贴输入与基础字数校验；
- 可配置 OpenAI API 地址、API Key、模型名；
- 模型清洗原文中的广告、无关链接、重复段落和口语赘词；
- 在不照搬原文措辞和段落顺序的前提下，重组为新的科普叙事；
- 自动决定页数（建议 4–12 页），每页生成标题、讲解正文、重点标注、口播稿和视觉布局建议；
- 以统一模板渲染为单个可离线打开的 HTML 文件；
- 在网页内预览、修改单页文字、重新生成单页、下载 HTML 与口播稿 Markdown。

### 暂不做

- 联网搜索、事实核查和引用管理；
- AI 配图、素材图库、语音、字幕、视频合成；
- 登录、多用户、云端存储、直接发布到平台；
- 爬取或批量导入第三方平台内容。

## 3. 用户流程

```text
粘贴文章
  → 选择账号风格 / 受众 / 口播语速
  → 调用模型生成“内容计划”
  → 解析并校验结构化结果
  → 预览逐页讲解卡与口播稿
  → 编辑或重生成某页
  → 导出 HTML + Markdown 口播稿 + JSON 项目文件
```

默认配置：中文、面向普通成年人、亲切但不过度煽动、每页约 90–180 字讲解正文、口播约 90–180 个汉字。页数由模型按内容密度和叙事完整度决定，而非固定为 8 页。

## 4. 内容生成原则

原文只作为素材与选题参考，不应被逐句改写。模型须：

1. 提取主题、可保留事实、核心问题及适合传播的案例；
2. 删除推广、来源不明的绝对化结论、重复表达和不可验证的个人经验；
3. 用新的切入角度、段落顺序、比喻、总结及互动问题重组内容；
4. 对无法从原文确定的事实使用审慎表述，不凭空补充数据、研究或引用；
5. 保留“待核实”标记供用户审核，而不是伪造权威性。

页面推荐叙事：封面问题 → 关键概念 → 原理拆解 → 常见误区/案例 → 总结与行动建议。模型可按文章调整，不强制套模板。

## 5. 技术方案

| 层级 | MVP 选型 | 原因 |
| --- | --- | --- |
| 后端 | Python 3.12 + FastAPI | 异步 API、类型定义和 OpenAPI 文档完善 |
| 模型 | OpenAI Python SDK | 先接 OpenAI；后续可用兼容 Base URL 替换服务商 |
| 结构化校验 | Pydantic v2 | 约束模型返回，避免 HTML 渲染不稳定 |
| 前端 | React + TypeScript + Vite | 编辑、预览、状态管理体验好 |
| 样式 | Tailwind CSS + CSS variables | 统一主题并方便以后增加风格包 |
| 数据存储 | 本地 JSON 文件 | 不需要数据库，项目可恢复和可导出 |
| HTML 导出 | Jinja2 模板 | 让内容与页面样式分离，导出文件可离线打开 |

后端不向前端暴露 API Key。密钥仅保存在本机 `.env` 或系统环境变量，配置接口只返回掩码后的状态。

## 6. 推荐目录

```text
cadence/
  backend/
    app/
      api/                 # FastAPI 路由
      core/                # 配置、异常、日志
      services/            # LLM、项目、导出服务
      prompts/             # 系统提示词与版本号
      schemas/             # Pydantic 输入/输出模型
      templates/           # Jinja2 导出模板
      main.py
    tests/
  frontend/
    src/
      components/
      pages/
      styles/
      types/
  data/projects/           # 本地项目 JSON，加入 .gitignore
  docs/
```

## 7. 核心数据结构

```json
{
  "title": "为什么熬夜后更容易觉得饿？",
  "source_summary": "原文素材的压缩摘要",
  "audience": "普通成年人",
  "style": "clear-science",
  "pages": [
    {
      "id": "page-01",
      "role": "hook",
      "title": "熬夜后的饥饿感，不只是意志力差",
      "body": "每页讲解正文……",
      "highlights": ["关键信息一", "关键信息二"],
      "visual_direction": "深色背景、月亮与食物的简约线条图",
      "narration": "30–60 秒中文口播稿……",
      "review_flags": ["原文未提供出处，建议核实具体数据"]
    }
  ],
  "closing_cta": "你有没有类似经历？",
  "generation_meta": {"prompt_version": "v1", "model": "gpt-…"}
}
```

`role` 枚举：`cover`、`hook`、`concept`、`explain`、`example`、`myth`、`summary`、`cta`。前端据此选择布局，但允许用户手动更换。

## 8. API 草案

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/generations` | 提交文章与生成设置，创建生成任务 |
| `GET` | `/api/generations/{id}` | 查询任务状态和结果 |
| `PATCH` | `/api/projects/{id}/pages/{page_id}` | 保存单页人工编辑 |
| `POST` | `/api/projects/{id}/pages/{page_id}/regenerate` | 按用户备注重生成单页 |
| `GET` | `/api/projects/{id}/export/html` | 下载独立 HTML |
| `GET` | `/api/projects/{id}/export/script` | 下载口播 Markdown |
| `GET/PUT` | `/api/settings/model` | 读取/更新模型名和 Base URL；密钥单独写入本地环境 |

生成任务首版可采用轮询；模型响应耗时明显时，后续改为 SSE 展示“正在提炼/正在规划/正在撰写”状态。

## 9. 模型调用设计

采用两步调用，质量比“一次直接吐 HTML”更稳定：

1. **内容规划**：输入原文和风格配置，输出主题、读者、叙事角度、页数理由和每页大纲。
2. **内容写作**：基于已确认规划，严格输出上述 JSON Schema。

服务端解析 JSON 后由 Pydantic 校验：至少 4 页、至多 12 页；标题不能为空；每页须有正文与口播稿；口播长度过短或过长时自动请求模型修订一次。失败时保留原始响应，向前端显示可读错误与“重试”操作。

系统提示词需要固定以下约束：中文输出；不复制原文连续句子；不捏造来源；正文和口播避免重复；口播自然、有停顿感；重点标注最多 3 条；不生成 HTML、Markdown 围栏或解释性前言。

## 10. 前端体验与视觉

界面分三栏：左侧为文章与设置，中间为可横向切换的讲解页预览，右侧为当前页字段编辑器和口播稿。首期内置一个 `clear-science` 风格：高留白、奶油白背景、墨黑正文、克制的蓝绿强调色、圆角卡片、大字号标题。移动端导出的讲解页按 9:16 视觉比例排版，适合后续截图制作小红书图文。

HTML 导出应内嵌全部 CSS、字体回退和项目数据；不依赖本地开发服务器。每页提供页码、统一页眉/页脚和“下一页”导航；打印样式按一页一张卡片输出。

## 11. 交付里程碑与验收

### M1：工程骨架

FastAPI、React、配置读取、健康检查、文章输入页能本地启动。

### M2：内容生成

能够用 OpenAI API 将一篇约 3,000 字中文文章生成合法项目 JSON；异常、超时与无效 Key 有明确提示。

### M3：编辑与导出

可预览全部页面、编辑并保存某一页，下载单一 HTML 与 Markdown 口播稿。

### M4：质量回归

准备 10 篇不同主题文章作为测试集。验收标准：每篇均生成 4–12 页；无 JSON 解析失败；每页均含正文、重点和口播；导出 HTML 在 Chrome 离线打开正常；人工抽检不出现大段照搬或凭空捏造数据。

## 12. 第二阶段预留

联网能力独立实现为 `research` 服务：先提取待核实主张，再检索优先级较高的权威来源，生成可追溯的证据包，最后由写作服务引用证据包重写。页面数据结构预留 `sources` 与 `fact_check_status`，但 MVP 不填充。

之后再添加配图提示词、图片生成、TTS、字幕时间轴和 FFmpeg 视频合成。它们消费已稳定的 `pages` 数据，不改变第一阶段核心协议。

## 13. 已知风险

- 原文来自其他创作者时，改写不等于自动获得转载或商用授权；产品需在输入区提示用户确认拥有使用权，并默认不保留原文。
- 科普内容可能包含医疗、金融、法律等高风险主题。MVP 应显示“仅供一般信息参考”，并将模型标记的待核实项突出展示。
- 模型生成的事实不能当作已核查结论。因此联网核验是第二阶段的必要能力，而非可有可无的装饰。
